# Intro

Let's write a CLI tool for bunny.net. It should be optimized for the usage by AI tools, but also be usable for humans.

  

# Tech stack

The tool should be written with the latest version of rust with clap and clap_complete. The goal is to have self contained binaries for all platforms generated by github actions for windows, mac and linux.

  

Do some online research how to write modern CLI tools using rust and and clap.

  

# Functionality

bunny.net is a cloud/edge platform. It offers an API for all their services. To make this API accessible to LLM and coding agents (as well as to humans), we'd like to build a CLI tool to control all bunny services via this API.

  

An LLM friendly documentation is available at: https://docs.bunny.net/llms.txt

Where the ones below https://docs.bunny.net/api-reference are probably most useful.

  

Also check well-known CLI tools like "az" or "gcloud" how they structure the command line options. I could imagine having something like `./hoppy pull-zone create --a=b --c=d` or `./hoppy storage-zone get --id=123`, where the first arg is the "service" (pull-zone, DNS, storage etc.) the second arg the command and then followed by input parameters with double dashes.

  

It's important to have a machine readable *and* a human readable output format that e.g. could be selected with the --format parameter like `--format=json`.

  

# Implementation hints

The bunny.net API specs are also available as OpenAPI specs: https://docs.bunny.net/openapi.md

  

Do some research if the http client can be generated with a code generator from these OpenAPI specs. The codegen tool should create modern rust code and still maintained.

  

The main AccessKey (API key) should be read from the environment variable BUNNY_API_KEY, so the tool can be called like: `BUNNY_API_KEY=abc-123 ./hoppy magic-containers ...`
